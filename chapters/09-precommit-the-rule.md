# Write the Rule Before Seeing the Answer

The operations manager has a four-project track record: four successful installations out of four. Another file has eight on-time launches in twelve records. The manager wants to use the first history and the treasurer wants to use the second. What would you do if neither knew which sponsor had said yes?

This chapter teaches you to make a decision auditable without claiming the firm can delete judgment. It starts before a spreadsheet result is available. Choose a comparison group, name a material uncertainty, and decide what observation will move the recommendation.

## Freeze a good question

Suppose four overdue installations were dropped from an early report because the projects had not finished settling warranty claims. Some of the remaining eight on-time projects are in the same operating conditions as the next build; others have different suppliers and equipment. Neither 4 / 4 nor 8 / 12 automatically estimates the new project's true probability. The narrow sponsor sample may omit failures. The broad file may mix irrelevant projects. The right response is to separate inclusion rules from outcome labels.

Start by writing the question as a dated event. “The bay can operate at required load without temporary equipment before June 30” is testable. “Installation goes well” is not. Decide which prior projects qualify, how to handle incomplete outcomes, and which records establish that the same event was met. If those records are too few for a reliable rate, state that limitation. Report a range of decision consequences instead of giving the small sample more precision than it has.

## Ask when the uncertainty changes the action

In a simplified independent decision, an upgrade pays an NPV of +$40,000 if prompt launch is achieved and an NPV of −$20,000 otherwise. These are values already measured at the same date and with the same valuation convention. Treat the weight `p` on prompt launch as an input, not as an empirical estimate. If the alternative is to decline for incremental value zero, the weighted project value is:

`p × 40,000 + (1 − p) × (−20,000) = 60,000p − 20,000`

The project breaks even at one-third under that model. This is the threshold for the expected-value calculation, not an instruction to tolerate the downside. If a downside loss could violate the company's cash reserve or a binding contract, the risk decision has another constraint. Paying for a more reliable launch date could be valuable if it changes the distribution or your ability to wait. It does not justify saying the initial uncertainty vanished.

**Attempt first.** Evaluate the expression with weights of 0.25 and 0.50. Identify the plausible section of the weight range where a better estimate could matter most. Write down which source could change the estimate and what decision you will take if it arrives after the payment deadline.

## Write a record someone can check later

A useful decision record is short. Keep the proposed action, the date, the assumption, the accepted evidence, the alternative you were prepared to take, and the threshold that would send you back. Save the first version before inviting critique. If another person or a model changes it, keep the old version and write one sentence about the new evidence. “It sounded more realistic” will not help an independent reader reconstruct the decision.

**Inspect the answer.** A draft says the new project had a one-in-three chance of success because the model breaks even at one-third. The statement confuses a demand for evidence with evidence that the threshold is met. Replace the sentence with a correct interpretation and a request for a concrete record.

**Transfer.** The unfavorable outcome worsens to −$30,000 while the favorable amount stays +$40,000. Recompute the threshold. Name a selection decision about prior project records that would be unacceptable if made after seeing which projects were successful.
